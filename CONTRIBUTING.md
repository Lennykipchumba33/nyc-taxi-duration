# Contributing

Thanks for helping improve this project. Work is organized to be reviewable and easy to continue asynchronously.

## Before opening a pull request

1. Open an issue for a non-trivial change and describe the problem, proposed approach, and acceptance criteria.
2. Keep the change focused; avoid mixing unrelated refactors with behavior changes.
3. Update the README or examples when setup, behavior, metrics, or limitations change.
4. Run the repository's documented tests and quality checks locally.
5. Do not commit credentials, private data, generated secrets, or large local datasets.

## Pull requests

Please include the motivation, implementation summary, validation performed, limitations, and any follow-up work. If the change affects model behavior or evaluation, include the dataset split, metric impact, and relevant trade-offs.

Maintainers may request documentation, tests, or clearer provenance before merging.
